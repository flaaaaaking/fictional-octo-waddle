# 五大人格反馈计划｜完整产品手册

这份手册说明产品定位、理论框架、访谈算法、判定方法、数字解读、系统流程、运行方案、测试方法、隐私与限制。

## 1. 产品定位

五大人格反馈计划是一个基于 Big Five 五因素模型、通过开放式对话收集跨情境行为证据的半结构化人格访谈工具。它不是 MBTI 类型竞猜，不是标准化心理量表，也不是临床诊断。

用户会得到：一题一答的自然访谈、五维和 15 个子特质、支持与反向证据、稳定模式、表面矛盾、人际风格、价值主题、优势、潜在盲区、证据可信度，以及可长期恢复报告的实验代码／访问码。

## 2. 五维与 15 个子特质

| 维度 | 关注内容 | 子特质 |
|---|---|---|
| 外向性 | 社交连接、表达、活动能量 | 社交性、果断性、活力水平 |
| 尽责性 | 组织目标、持续执行、兑现责任 | 条理性、执行力、责任感 |
| 开放性 | 观念、想象、审美与复杂经验 | 求知好奇、审美敏感、创造想象 |
| 宜人性 | 信任、合作、理解与边界 | 同情心、尊重性、信任倾向 |
| 情绪敏感性 | 压力觉察、情绪波动与恢复 | 焦虑敏感、情绪波动、低落敏感 |

高低没有道德好坏。较低社交性可以意味着独处耐受；较高情绪敏感性可以带来更早的风险觉察。报告必须同时解释功能、代价和情境。

## 3. 访谈运行流程

1. 前端读取当天剩余名额；
2. 用户领取名额；
3. 服务端创建会话并生成随机实验代码／访问码；
4. 用户一次回答一个开放问题；
5. 每轮更新子特质覆盖、证据、矛盾和待追问缺口；
6. 继续追问信息不足或互相矛盾的部分；
7. 信息充分或达到停止条件后生成报告；
8. 报告保存在原会话中；
9. 用户以后使用同一代码恢复访谈或查看报告。

## 4. 问题选择算法

每轮优先选择：尚未覆盖的子特质；只有抽象自评而缺少行为例子的部分；只在单一情境出现、需要交叉验证的结论；存在反向证据、需要寻找切换条件的表面矛盾；或者当前最能增加信息量的问题。

问题不得提前透露正在测哪个维度。每题后的观察只做中性复述和暂时判断，不宣布最终人格结论。

## 5. 证据账本

15 个子特质分别维护 0–3 的覆盖度：

- 0：尚未涉及；
- 1：只有单一或抽象证据；
- 2：存在具体行为证据；
- 3：已跨情境验证，并记录条件或反例。

重点证据记录子特质、方向、情境、行为、条件和强度。系统最多保留 24 条区分度最高的证据，同时维护表面矛盾、待追问缺口和连续无新增信息次数。

## 6. 判定原则

- 不凭关键词直接贴标签；
- 同一结论需要多个情境交叉验证；
- 区分稳定倾向、当前状态、角色要求、环境限制、身体状况和后天技能；
- 同时保留支持证据与反向证据；
- 新证据不支持旧判断时允许修正；
- 夸张或黑色幽默不自动等同真实意图；
- 不输出疾病、人格障碍、道德优劣或污名化标签。

## 7. 停止条件

通常目标为 30–50 个核心问题，最大 66 题。只有五维均有多个独立情境、至少 10 个子特质覆盖度达到 2、关键矛盾已解释，且连续两题没有明显新增信息时，才建议自然结束。用户疲惫或主动结束时可以提前报告，但必须降低可信度并列出缺口。

## 8. 倾向区间

例如“开放性 70–81”，表示本次访谈证据支持该维度大致落在偏高区间。它只用于本次访谈内部比较和解释，不是人群百分位、正式常模成绩或精确心理测量。

后台可以使用区间中点形式的 score 进行五维排序；用户界面优先显示区间，避免制造虚假精确感。相近或重叠区间不应解释为显著差异。

## 9. 证据可信度

例如“72 / 100 证据可信度”，评估的是结论有多少证据支持，不是人格强度。它主要考虑具体行为例子、跨情境一致性、条件与反例、未解释矛盾和子特质覆盖度。

所以“倾向偏高但可信度较低”和“倾向中等但可信度较高”都可能成立。

## 10. 报告结构

报告包括原创综合称号、整体摘要、五维排序、每维三个子特质、支持证据、反向证据、功能、代价、稳定模式、表面矛盾、人际互动、价值主题、优势、潜在盲区、可变化部分、总体可信度和信息缺口。

“静水探路者”之类的称号只是叙事入口，不是固定人格类型。

## 11. 视觉与角色系统

品牌采用蓝白和浅灰白；紫、蓝、橙、绿、珊瑚粉仅用于五维识别。已确认的全家福是唯一角色身份母版，01–05 单人图直接从母版裁出，因此人物发型、服装、道具、线条和颜色完全一致。报告使用浅色卡片、高对比文字，不使用会让白底人物产生怪异边缘的深色背景。

## 12. 系统架构

GitHub Pages 承载静态前端；Cloudflare 隧道把 HTTPS 请求转发到服务器；Node.js 服务处理每日名额、访问码、会话、报告和 Provider；Provider 可选择 mock 或 DeepSeek。

DeepSeek API Key 只能放在服务器环境变量中，不能写入 GitHub、runtime-config.js 或浏览器代码。

主要配置：AI_PROVIDER、DEEPSEEK_API_BASE_URL、DEEPSEEK_API_KEY、DEEPSEEK_MODEL、DAILY_NEW_SESSION_LIMIT、MAX_TURNS_PER_SESSION、SESSION_TTL_HOURS、ALLOWED_ORIGINS。

## 13. 数据与恢复

轻量版本使用 data/store.json。访问码只以 SHA-256 哈希形式作为索引保存；明文代码返回给用户。会话保存问题、回答与报告，以支持长期恢复。文件存储适合小规模项目，长期运营应迁移到有备份的数据库。

## 14. mock 与 DeepSeek

mock 模式使用固定问题和固定演示报告，只验证页面、接口、排序和恢复流程，不能代表真实个体分析。DeepSeek 模式才会根据每位用户的真实回答动态追问和生成报告。

## 15. 发布运行

GitHub Pages 使用仓库根目录静态副本；服务器使用 public 和 server 目录。更新前端时两份静态文件必须同步。发布后需要检查 Pages、隧道、名额接口、全家福、五张单人图、报告恢复和前端是否泄露密钥。

## 16. 隐私与限制

访问码等同报告查看凭证，公开分享带 code 的链接等同公开报告。产品不能用于医疗诊断、招聘淘汰、司法、保险、信贷或其他高风险决定。模型输出可能漂移；临时隧道地址可能变化；文件存储缺少大型数据库的并发与备份能力。

- 名额与访问码：server/store.js

- 页面：public/index.html
- 页面逻辑：public/app.js
- 视觉：public/theme-v4.css
- 角色母版：public/bigfive-guides-v2.png
- 单人图生成：scripts/build-character-crops.ps1
- 自动验收：scripts/smoke-test.ps1
- 实验记录：docs/experiments/
